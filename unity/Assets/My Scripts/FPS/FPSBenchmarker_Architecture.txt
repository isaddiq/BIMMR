MEMORY FOOTPRINT
----------------

Runtime overhead (when not benchmarking):
  • 2 event subscriptions: ~16 bytes
  • State enum: 4 bytes
  • Boolean flags: ~8 bytes
  • Total: < 100 bytes

During benchmarking (worst case):
  • FPS samples: 3,600 floats × 4 bytes = 14.4 KB
  • Memory samples: 3,600 longs × 8 bytes = 28.8 KB
  • Total: ~43 KB

CPU overhead:
  • Idle: 0% (no Update logic)
  • Warmup: < 0.1% (timer check only)
  • Sampling: < 0.5% (FPS calculation + 1 GC call per frame)

Example 1: Auto-benchmark every model
  [SerializeField] private bool autoBenchmarkOnLoad = true;

Example 2: Benchmark via button
  public void OnBenchmarkButtonClicked()
  {
      FindObjectOfType<FPSBenchmarker>().StartBenchmarkForCurrentModel();
  }

Example 3: Benchmark sequence of models
  IEnumerator BenchmarkAllModels()
  {
      var benchmarker = GetComponent<FPSBenchmarker>();
      
      foreach (var model in modelList)
      {
          moduleManager.LoadModel(model);
          yield return new WaitForSeconds(2f); // Let model load
          benchmarker.StartBenchmarkForCurrentModel();
          yield return new WaitForSeconds(75f); // 15s warmup + 60s sample
      }
  }


TROUBLESHOOTING GUIDE
---------------------

Issue: Benchmark never starts
  Check: Is moduleManagerReference assigned?
  Check: Does ModuleManager implement IBimModelProvider?
  Check: Is a model actually loaded?
  Check: Enable Debug Logs to see state transitions

Issue: Results not saved
  Check: Unity console for file path (should be /storage/emulated/0/...)
  Check: App has storage permissions on Quest
  Check: No exceptions in console during SaveResultsToCSV()

Issue: Low sample count
  Check: Is frame rate extremely low? (< 60 FPS = fewer samples)
  Check: Was benchmark cancelled early?
  Check: Check "notes" column in CSV for warnings

Issue: Memory constantly growing
  This is normal if your models are large
  Compare avgMemoryMB between multiple runs of same model
  If memory increases each run → possible memory leak

Issue: Inconsistent results between runs
  Check: Same Quest power/thermal state?
  Check: Other apps running in background?
  Check: Model fully loaded before warmup starts?
  Tip: First run is often slower due to shader compilation


PERFORMANCE CONSIDERATIONS
---------------------------

✓ Uses Time.unscaledDeltaTime (not affected by Time.timeScale)
✓ GC.GetTotalMemory(false) is lightweight (no garbage collection triggered)
✓ FPS calculation is simple division (minimal CPU)
✓ Statistics calculated only once at end (not per-frame)
✓ File I/O only happens at benchmark completion
✓ No memory allocations during sampling (List pre-allocated)

Quest 3 Performance Tips:
• Keep models under 500MB
• Use texture compression (ASTC)
• Optimize draw calls
• Use occlusion culling
• Target 72 FPS native refresh rate
• Watch for thermal throttling
